# Open Source Strategy

Octopus should be open source in product, code, governance, deployment, and community operations.

## License choice

Octopus uses AGPL-3.0-or-later. This protects the project from being taken private as a hosted service without sharing improvements back.

## What must stay open

- Core risk engine
- Web dashboard
- API service
- Rule packs
- Deployment scripts
- Documentation
- Community education content
- Safety and privacy policies

## What should not be monetized through lock-in

- User data
- Basic debt-pressure checks
- Basic emergency-readiness checks
- Basic scam education
- Self-hosted deployment

## Sustainable model options

Octopus can remain fully open source while supporting paid services around it:

1. Managed hosting
2. Implementation support for NGOs and community groups
3. Custom local rule packs
4. Privacy and security audits
5. Enterprise support
6. Training and workshops

## Community trust requirements

- Public roadmap
- Clear issue labels
- Transparent releases
- Security policy
- No hidden affiliate incentives
- No sale of personal financial data
